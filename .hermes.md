## Commit Format

Every commit must follow:

```
[AGENT_NAME] type(scope): description
```

- **AGENT_NAME:** `HERMES`
- **Allowed types:** `feat`, `fix`, `docs`, `refactor`, `chore`, `test`, `ci`
- **Scope:** Short noun phrase for the area affected
- **Description:** Imperative mood, no trailing period

**Examples:**
```
[HERMES] feat(nav): add Articles menu item linking to manifesto
[HERMES] fix(website): address Poolside AI + OpenCode PR #42 review feedback
[HERMES] docs(governance): write handoff record for post-launch content corrections
[HERMES] feat(theme): add dark mode with toggle
```

**Template:** `templates/commit-message.md`

## Pull Request Workflow (Non-Negotiable)

- **Always work from a feature branch** — never commit directly to `main`
- **Always open a Pull Request** — never push directly to `main` or protected branches
- **Use the NLT PR template:** `PULL_REQUEST_TEMPLATE/agent-contribution.md`
- **PR description must include:** Agent Contribution Checklist, scope declaration, changes summary, build verification, governance/handoff notes
- **PR reviewers on this repo:** CodeRabbit (automated), Poolside AI, OpenCode, kilo-code-bot, human approvers (JDUB1216)
- **Attribute review comments to the correct source** — don't guess who said what

| Guardrail | Details |

## Escalation Protocol

**Escalate to Joshua immediately when:**
- Task scope is unclear or conflicts with existing work
- An architectural or deployment decision is required
- A blocker cannot be resolved by the agent
- An ethical concern arises
- LLM provider or external service selection is needed

**Escalation format:** `templates/escalation.md`

**Escalation file location:** `docs/escalations/[date]-[topic].md`

**GitHub issue template:** `ISSUE_TEMPLATE/agent-escalation.md`

---

## Handoff Protocol

At the end of every significant session:

1. Update `docs/active-threads.md` in the working repo
2. Write a handoff record to `docs/agent-log/handoffs/` using `templates/handoff-record.json`
3. Document any open escalations in `docs/escalations/`
4. Summarize decisions made and decisions pending

**Handoff record location:** `docs/agent-log/handoffs/[date]-[session-id].json`

**Handoff template:** `templates/handoff-record.json`

## Active Thread Management

- Read `docs/active-threads.md` at session start
- Update it during the session as threads are opened or resolved
- Leave it accurate at session end

**Thread entry format:**
```markdown
### Thread: [Thread ID]
**Status:** [open | blocked | resolved]
**Owner:** [Agent or human responsible]
**Started:** [ISO 8601 timestamp with offset]
**Last updated:** [ISO 8601 timestamp with offset]
**Summary:** [One-paragraph description]
**Blockers:** [Any blocking conditions]
**Next action:** [Specific next step required]
```

- **Production:** `elevaitionfoundation.org` (intentional brand spelling — NOT a typo)

## Common Mistakes to Avoid

1. **Pushing directly to main** — always use a feature branch + PR
2. **Forgetting to update active-threads.md** — do it at session start AND end
3. **Writing handoff records with stale file lists** — verify `files_modified` matches actual diff
4. **Forgetting to verify the build** — run `npm run build` before every push
5. **Using wrong PR template** — always use `PULL_REQUEST_TEMPLATE/agent-contribution.md`
6. **Misattributing review comments** — Poolside AI, OpenCode, kilo-code-bot, CodeRabbit, and JDUB1216 all review PRs
7. **"Fixing" the domain** — `elevaitionfoundation.org` is intentional
8. **Adding pages without nav entries** — update both `Header.astro` and `Footer.astro`
9. **Skipping handoff records** — every significant session needs one
10. **Not escalating** — when in doubt, escalate. It's not failure; it's correct protocol.
